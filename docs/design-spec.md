# 개인용 영상 압축 앱 설계안

상태: 구현 전 검토안 · 2026-11-12

## 작업 계약

```yaml
mode: change
risk: medium
goal: Windows와 macOS에서 주요 영상 형식을 간편하게 압축하고 예상·실제 절감량을 표시하는 개인용 앱
non_goals: 영상 편집, 클라우드 업로드, 계정, 자동 배포, 유료 서비스, 원본 삭제
affected_repositories: 현재 기존 저장소 없음; 승인 후 outputs/video-compressor에 새 프로젝트 생성
constraints: 한국어 UI, 로컬 처리, 원본 보존, 단순한 기본 화면, 압축률·화질 무조건 보장 금지
acceptance_criteria: 파일 추가 → 강도 선택 → 압축; 추정과 실제 절감량 구분; 취소·실패 안전 처리; Windows·macOS 설치 파일과 실제 실행 검증 상태를 구분해 제공
verification: Rust 단위 테스트, TypeScript 검사·UI 빌드, 생성한 영상으로 FFmpeg 통합 검증, 실제 화면 확인; OS별 빌드·실행은 별도 증거 기록
required_user_decisions: 제안 기술 구성과 아래 1차 구현 범위 승인
```

## 사용자 요구와 제안 구분

확정 요구: 개인용, Windows와 macOS, 자주 쓰는 영상 확장자 지원, 적은 화질 손실, 용량 감소 표시, 최대한 간편한 UI, 디자인 스킬 적용. Rust의 적합성을 설명할 것.

이하 기술 선택, 세부 동작, 기본값은 구현자 제안이다. 아직 사용자 승인으로 간주하지 않는다.

## 접근 방식

| 방식 | 장점 | 비용·제약 |
|---|---|---|
| Tauri 2 + Rust + React/TypeScript + FFmpeg — 제안 | 두 OS에서 UI 재사용, Rust로 작업·파일·자식 프로세스 관리, UI 디자인 도구 활용 | 플랫폼별 WebView 차이와 FFmpeg 배포 구성 검증 필요 |
| Electron + TypeScript + FFmpeg | 성숙한 데스크톱 생태계, 일관된 Chromium 렌더링 | Chromium/Node 런타임을 함께 배포 |
| Rust 네이티브 UI + FFmpeg | Rust 중심 코드 구성 | 이 도구의 압축 병목을 해결하는 이점은 작고, 세밀한 UI 표현·접근성 검증 부담 |

제안 스택: Tauri 2, Rust stable, React, TypeScript, Vite, 기본 CSS, FFmpeg/ffprobe 외부 실행 파일. 버전은 구현 시작 시 실제 설치 가능한 안정 버전으로 고정하고 lockfile을 포함한다. 별도 서버·DB·계정·대형 UI 라이브러리는 필요 없다.

Rust는 파일·프로세스·취소 상태를 관리한다. 압축 연산은 FFmpeg와 x265/SVT-AV1 등의 인코더가 담당한다. Rust 사용 자체가 같은 인코더의 압축 속도를 높이지는 않는다. 속도·화질·파일 크기는 인코더, 설정, 하드웨어에 좌우된다.

## 첫 버전 사용 흐름

1. 파일을 끌어놓거나 기본 파일 선택창에서 여러 개 추가한다.
2. `화질 우선 / 균형 / 용량 우선` 중 선택한다. 기본은 `균형`이다.
3. 선택 사항인 `예상 용량 확인`을 누르면 시험 압축으로 추정치를 계산한다. 분석을 기다리지 않고 전체 압축을 시작할 수도 있다.
4. 저장 폴더를 고르고 `압축 시작`을 누른다. 여러 파일은 한 번에 하나씩 처리한다.
5. 파일별 진행률과 대략적인 남은 시간을 표시한다. 끝나면 실제 용량·절감률과 `폴더 열기`를 제공한다.

작업 중 파일 추가·설정 변경은 잠그고 취소를 제공한다. 실패한 파일은 이유를 표시하고 나머지 대기 파일을 계속 처리한다. 취소는 현재 파일과 남은 대기를 멈춘다. 이미 완료된 결과는 보존한다.

## 화면 제안

모드: Operate. 한 창, 밝은 중성 배경, 짙은 본문, 절제된 녹색 강조, OS 기본 글꼴. 첫 화면에서 주요 동작 하나가 명확해야 한다. 사이드바·대시보드·그래프·코덱 전문 용어를 기본 화면에 배치하지 않는다. 최소 720×560 창과 키보드 조작을 고려한다. 시각 방향의 세부 토큰과 실제 렌더링 검증은 승인 후 UI 구현에서 확정한다.

```text
영상 압축                                  [파일 추가]

  여기에 영상을 놓아주세요

  여행.mov         1.20 GB → 약 540 MB
                   예상 약 55% 감소 · 시험 압축 기준

  압축 강도       화질 우선   [균형]   용량 우선
  [예상 용량 확인]                      세부 설정 ▾
  저장 위치       원본 폴더 / Compressed      [변경]

                                      [압축 시작]
```

숫자는 화면 설명용 예시이며 제품에서 기본 추정값으로 사용하지 않는다. 분석 전에는 `예상 용량 확인 가능`, 계산 중에는 `시험 압축 중`, 실패 시에는 `예측 불가 — 전체 압축 가능`으로 표시한다. 실제 완료 전에는 절대 `55% 감소 완료`처럼 표시하지 않는다.

빈 상태, 파일 분석 중, 준비됨, 예상 계산 중, 압축 중, 완료, 취소, 파일 오류, 지원 제한 상태를 구현한다. 상태는 글자로도 표시하며 색에만 의존하지 않는다. 모션은 상태 전환에만 짧게 사용하고 모션 감소 설정을 따른다.

## 형식과 압축 정책

- 입력 후보: MP4, MOV, MKV, AVI, WebM, WMV, FLV, MPEG/MPG, TS, MTS, M2TS, M4V, 3GP. 확장자는 파일 선택을 돕는 필터이며, 실제 지원 여부는 ffprobe 결과와 번들에 포함된 디코더로 판단한다. 모든 코덱·손상 파일·암호화 파일 지원을 보장하지 않는다.
- 기본 출력: MP4 + 소프트웨어 H.265/x265. 세 단계는 같은 인코더의 품질 설정만 바꾼다. 해상도와 재생 타이밍을 기본 유지한다. 정확한 RF 값은 샘플 검증 후 정한다.
- 접힌 세부 설정: `재생 호환성 우선(H.264)` / `기본(H.265)` / `압축 효율 우선(AV1)`, MP4 또는 MKV 출력. AV1은 포함한 인코더가 실제 사용 가능한 경우에만 선택 가능하다.
- H.265/AV1 결과는 재생 앱에 따라 코덱 지원이 필요할 수 있다. 호환성 옵션 옆에 짧게 설명한다. GPU 자동 선택은 첫 버전에서 제외해 예상 계산과 실제 압축의 설정을 일치시킨다.
- 오디오·자막·첨부 스트림을 검사하고 보존한다. MP4로 복사할 수 없는 자막·첨부·오디오가 있으면 기본 저장 형식을 MKV로 제안하고 `트랙 보존을 위해 MKV로 저장`이라고 표시한다. 다중 오디오도 보존한다. 사용자가 MP4를 강제 선택한 경우 지원하지 않는 트랙을 몰래 버리지 않고 MKV 안내로 해당 작업을 보류한다. 복수 영상 트랙·특수 데이터 트랙은 각각 보존 가능성을 검사하고 불가능한 경우에만 지원 제한을 설명한다.
- 오디오는 MP4/MKV에 호환되면 복사한다. 변환이 필요한 경우 AAC 변환 여부를 세부 정보에 명시한다. 무음 영상도 처리한다.
- 회전 메타데이터, 가변 프레임 타이밍, 홀수 해상도는 검사·검증 대상이다. 픽셀 형식·패딩 변경이 필요한 경우 작업 정보에 표시한다.
- 일반 SDR 외에 정적 HDR10·HLG는 10비트 영상 및 색 공간·전달 함수·정적 HDR 메타데이터를 보존하는 경로를 포함한다. 지원 확인된 H.265 경로를 기본 사용하며, 검증되지 않은 다른 코덱 조합은 선택을 제한한다. Dolby Vision·HDR10+ 동적 메타데이터·인터레이스·알파 영상은 보존 가능한지 확인하고 불가능한 경우 지원 제한을 설명한다. 화질·색·투명도 손실을 감추는 자동 SDR 변환은 하지 않는다. 단순히 HDR 태그가 있다는 이유로 SDR 경로에 통과시키지 않는다.
- 완전 무손실 모드는 용량을 크게 줄이는 기본 목적에 맞지 않아 첫 버전 UI에서 제외한다. `화질 우선`을 무손실로 표기하지 않는다.

## 용량 표시

- 예상: 영상 전반의 서로 겹치지 않는 여러 짧은 구간을 동일 코덱·품질·해상도·프리셋으로 시험 압축한다. 짧은 영상은 가능한 구간 또는 전체를 사용한다. 처리 시간으로 전체 크기를 추정하고 오디오·컨테이너 비용을 반영한다.
- 샘플 구간 수·길이, 비트레이트 가중, 오차 범위는 구현자가 명시적 알고리즘으로 정하고 테스트한다. 통계적으로 검증하지 않은 ±10% 같은 신뢰구간을 표시하지 않는다. 결과는 `약`으로 표시하고 장면 변화에 따라 실제와 다를 수 있음을 안내한다.
- 설정 변경, 파일 변경, 인코더 변경 시 이전 추정치를 즉시 무효화한다. 예측 실패가 전체 압축 불가를 뜻하지는 않는다.
- 실제: `절감 바이트 = 원본 바이트 − 결과 바이트`, `절감률 = 절감 바이트 / 원본 바이트 × 100`. 합계는 파일별 백분율 평균 대신 전체 바이트 합계로 계산한다.
- 실제 결과가 같거나 더 크면 `감소 없음` 또는 `N% 증가`로 표시한다. 더 큰 결과는 자동 최종 저장하지 않고 임시 파일을 정리하며 `원본 유지 · 압축 이득 없음`으로 끝낸다.
- 크기 단위와 표시 반올림을 통일하고, 0바이트·재생 시간 미상·무한대·음수 표기를 방지한다.

## 파일·프로세스 경계

FFmpeg/ffprobe는 사용자에게 별도 설치를 요구하지 않도록 OS·CPU 아키텍처별로 동봉한다. 개발 중 시스템 실행 파일을 사용할 경우에는 경로와 버전을 명시하며 배포 준비 완료로 간주하지 않는다. 실제 포함한 바이너리의 라이선스와 소스 제공 조건에 맞는 고지·출처를 함께 제공한다.

Rust의 고정된 명령 인자 생성기를 사용하며 셸 명령 문자열을 만들지 않는다. UI는 임의 실행 파일·명령 인자를 지정할 수 없다. 입력은 사용자가 선택한 로컬 정규 파일로 제한하고, 불필요한 네트워크 프로토콜·권한을 차단한다. 작업 식별자와 입력 허용 목록은 Rust에서 관리한다.

출력은 기본 `원본폴더/Compressed/이름_compressed.mp4`로 하되 사용자가 고른 폴더로 변경 가능하다. 기존 파일은 덮어쓰지 않는다. 같은 폴더의 고유한 임시 경로에 쓰고 성공 종료·재생 가능한 영상·크기를 확인한 뒤 최종 이름으로 충돌 없이 확정한다. 원본과 같은 경로·심볼릭 링크 대상에는 출력하지 않는다. 실패·취소 시 해당 작업이 소유한 임시 파일만 정리한다.

예측과 전체 압축은 중첩 실행하지 않는다. 시간 제한과 취소 시 자식 프로세스 종료·회수, 앱 종료 시 정리, 저장 공간 부족, 읽기/쓰기 권한 오류를 처리한다. 로그에는 사용자 파일의 미디어 내용이나 자격 증명을 남기지 않는다.

## 배포·검증 범위

대상은 Windows x64, macOS Apple Silicon 및 Intel용 설치 가능한 앱이다. 소스·플랫폼별 빌드 구성도 제공한다. 최소 OS 버전은 고정한 Tauri/WebView와 FFmpeg 빌드에 맞춰 기록한다. Windows ARM은 첫 버전에서 제외한다.

현재 작업 환경에는 Rust, Node, FFmpeg/ffprobe가 존재한다. 기존 코드·Git 저장소는 없다. macOS에서 수행한 검사와 Windows에서 수행한 검사를 구분한다. Windows 빌드/실행 환경을 확보하지 못한 경우 해당 설치 파일 생성/런타임 검증은 미완료로 기록하고 양 OS용 앱 완료라고 주장하지 않는다. 플랫폼별 빌드 구성을 만들어도 실제 실행 검증을 대체하지 않는다. 서명·공증·스토어 게시·외부 CI 실행·계정·유료 인증서 등록은 이 작업이 자동으로 승인하지 않는다.

검증 계획: 절감량 계산·추정치 무효화·설정과 명령 생성 단위 테스트; 한글/공백/특수 문자 파일명; 입력과 출력 충돌; 무음·회전·VFR·손상 파일·지원 제한 감지; 다중 오디오/자막 트랙 보존; HDR10/HLG 색 정보·비트 심도·메타데이터 보존과 실제 표시 확인; 실제 생성 영상으로 분석→예측→압축→결과 검사; 취소·실패 시 원본 불변 및 임시 파일 정리; UI 빌드·타입 검사 및 빈/진행/완료/오류 화면 렌더링과 키보드 확인.
