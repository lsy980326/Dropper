# v0.2.0 엔진 소스와 배포 검증

## 제공 방식

[릴리스](https://github.com/lsy980326/Dropper/releases/tag/v0.2.0)의 설치 파일 옆에 대응 소스 다운로드를 안내하고, 같은 릴리스에서 소스 묶음과 체크섬을 무료로 제공합니다. 일반 프로젝트 홈페이지 링크만으로 대신하지 않습니다. [GPL v3 §6(d)](https://www.gnu.org/licenses/gpl-3.0.html#section6)의 네트워크 소스 접근 방식을 기준으로 자료를 준비했으며, [FFmpeg 공식 안내](https://ffmpeg.org/legal.html)의 버전 일치·패치·빌드 방법·고지 항목을 대조했습니다.

## Apple Silicon

번들의 `manifest.json`에 적힌 모든 파일을 실제 실행용 앱의 SHA256과 대조했습니다. FFmpeg 8.0.1_4와 외부 라이브러리 8개의 설치된 Homebrew 레시피를 보존하고, 레시피의 고정 체크섬으로 소스 아카이브·패치를 수집했습니다. x264는 정확한 Git 커밋에서 소스를 아카이브했습니다. FFmpeg·x265의 원격 패치와 libvpx 레시피에 내장된 패치를 포함합니다.

FFmpeg의 SVT-AV1 호환 패치 URL은 Git 이메일 형식의 메타데이터를 재생성해 이전 Homebrew 체크섬과 달랐습니다. 고정 커밋 `a5d4c398b411a00ac09d8fe3b66117222323844c`의 GitHub 원문과 코드 변경부가 같음을 대조했습니다. 원래 예상 해시·수집 해시·차이 설명을 모두 소스 묶음에 기록했고, 해시가 다르다는 사실을 숨기거나 다른 소스로 자동 대체하지 않았습니다.

## Intel

기존 Evermeet 9.0.2는 제공자 패치·빌드 스크립트와 일부 의존성 소스를 확인할 수 없었습니다. 따라서 기존 바이너리를 그대로 두고 소스 제공 완료로 표시하지 않고, 다음 고정 소스에서 FFmpeg/ffprobe를 새로 빌드했습니다.

- FFmpeg 8.0.1 + 소스 묶음의 패치 2개
- x264 r3222 · 커밋 `b35605ace3ddf7c1a5d67a2eb553f034aef41d55`
- x265 4.1 + CMake 호환 패치 2개 · 8/10/12비트 정적 구성
- dav1d 1.5.3 · SVT-AV1 4.0.1

macOS 12.0 대상으로 교차 컴파일했고, 비시스템 동적 라이브러리를 요구하지 않음을 확인했습니다. 새 엔진 ZIP에 라이선스·저작권 고지·소스 다운로드 주소를 포함하며, 준비 스크립트는 필수 고지가 없으면 중단합니다. 기존 앱 코드의 서명 외 섹션 18개가 같은지 비교했고, 재패키징한 앱의 ad-hoc 서명·모든 엔진 리소스 해시·DMG 체크섬을 검증했습니다.

소스 묶음의 `recipes/intel-bootstrap.sh`와 두 빌드 단계로 재빌드할 수 있습니다. NASM·pkgconf는 임시 경로에 빌드하고 Meson·Ninja도 임시 가상환경에 준비합니다. 실제 사용한 도구 버전과 빌드 설정을 포함합니다. 호스트에 Rosetta가 없어 Intel 바이너리의 실제 실행은 검증하지 않았습니다.

## Windows

설치 프로그램에서 추출한 FFmpeg의 버전 문자열이 `n8.1.3-35-gf1acb0a266`임을 확인했습니다. 정확한 소스 커밋은 `f1acb0a2666c78d92688f4c3d2803a132f5590f6`입니다.

- 공식 [빌드 실행 43017921659](https://github.com/FFmpeg-Builds/FFmpeg-Builds/actions/runs/43017921659), 제공자 커밋 `c9fe5114060e507409f7ee07edfd82efaf25d767`
- 당시 CI 소스 캐시의 SHA256을 공식 artifact digest와 대조하고, 실제 Windows 빌드가 사용한 소스 캐시 97개를 보존
- FFmpeg·제공자·crosstool-ng의 정확한 커밋 아카이브와 패치·빌드 설정 보존
- 캐시에 포함되지 않은 rav1e의 Rust 소스, Kvazaar의 greatest, dav1d의 checkasm 추가
- Rust 의존성은 실제 빌드 로그·잠금 파일과 대조하고 공식 crates.io 아카이브의 SHA256을 검사

rav1e의 갱신된 Cargo.lock은 원본 artifact가 아니라 고정 원본과 로그에 나온 변경 3개를 재구성한 자료임을 명시합니다. 원래 잠금 파일, 재구성 자료와 근거를 함께 제공합니다. 원본 97개 캐시 아카이브는 변경하지 않고 파일별 해시를 기록합니다. 원본 캐시 용량이 파일당 2GiB 제한을 넘으므로 기본 소스 묶음과 OpenSSL 원본 캐시를 두 파일로 제공합니다. 기본 묶음의 `external-source.json`이 추가 파일의 URL·해시·배치 경로를 지정합니다. **두 파일을 함께 받아야 전체 소스**입니다. Rust 잠금 파일에 대응하는 275개 패키지를 모두 제공하며, 재구성 잠금 파일과 공급된 소스로 `cargo metadata --locked --offline`의 205개 패키지 그래프가 해석되는 것을 확인했습니다.

GCC 도구체인은 `crosstool-ng fbb637297fef385204304f5ee32a168ea6145280`, GCC 16.2.0으로 확인했습니다. 정적 GCC 런타임에는 [Runtime Library Exception 3.1](https://www.gnu.org/licenses/gcc-exception-3.1.html) 고지와 정확한 출처를 보존합니다. 예외의 적용 조건은 [공식 FAQ](https://www.gnu.org/licenses/gcc-exception-3.1-faq.html)에 따릅니다. 빌드 도구와 링크된 런타임을 같은 것으로 취급하지 않습니다.

## 검증의 범위와 유지

소스 버전·패치·빌드 자료·라이선스와 파일 무결성을 대조한 기록입니다. 도구체인/SDK가 달라져도 실행 파일의 모든 바이트가 같다는 재현성 주장이나 Windows·Intel 실기기 실행 검증을 대신하지 않습니다. 앱 자체 코드의 라이선스는 이 작업에서 정하지 않았습니다.

설치 파일을 유지하는 동안 해당 소스 묶음과 고지도 유지합니다. 엔진을 변경하면 이 자료를 재사용하는 대신 새 바이너리와 실제 소스를 다시 대조합니다. 소스와 빌드 캐시는 Git에 넣지 않고 릴리스에 제공하며, 업로드 해시를 확인한 로컬 임시 산출물은 정리합니다.
